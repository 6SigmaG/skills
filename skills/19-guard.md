# /guard 深度解构

> **角色：** 全面安全模式（Full Safety）
> **定位：** 同时激活 /careful（危险命令警告）和 /freeze（编辑范围限制）
> **类型：** 组合型 Skill——自身无新逻辑，是两个安全 Skill 的捆绑激活
> **allowed-tools：** Bash, AskUserQuestion
> **来源：** `guard/SKILL.md`

---

> **结构说明：** 本文极度精简，因为 /guard 本质是一个组合快捷方式。

## 一、为什么需要这个 Skill

**问题：** 在高风险场景（如操作生产环境、修改关键模块）中，你需要同时启用命令警告和编辑范围限制。分别运行 `/careful` 和 `/freeze` 需要两步。

**gstack 的方案：** 一个命令启用全部防护——`/guard`。

---

## 二、工作流程

```
用户输入 /guard
       │
       ▼
"你想限制编辑范围到哪个目录？"
       │
       ▼
用户输入路径
       │
       ▼
同时激活两层防护：
┌─────────────────────────────────┐
│ 1) 危险命令警告（/careful）      │
│    rm -rf, DROP TABLE, etc.     │
│    → 警告但可覆盖               │
│                                 │
│ 2) 编辑范围限制（/freeze）       │
│    Edit/Write 限制在指定目录     │
│    → 硬阻止                     │
└─────────────────────────────────┘
```

---

## 三、解除方式

- `/unfreeze` — 只解除编辑范围限制，命令警告仍然生效
- 结束会话 — 解除全部防护

---

## 四、Prompt Engineering 可迁移模式

### 模式：组合快捷方式

将多个安全机制捆绑为一个命令，降低使用门槛。如果安全功能需要用户记住 3 个命令才能完整启用，大多数人不会用。一个命令 = 更高的采用率。

**设计哲学：** 安全的最大敌人不是技术，而是使用摩擦。
