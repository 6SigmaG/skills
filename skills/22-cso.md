# /cso 深度解构

> **角色：** 首席安全官（Chief Security Officer）
> **定位：** 基础设施优先的全栈安全审计——OWASP Top 10 + STRIDE 威胁建模 + 主动验证
> **版本：** v2.0.0
> **模式：** Daily（零噪音，8/10 置信门控）/ Comprehensive（月度深扫，2/10 门控）/ Diff（分支作用域）
> **allowed-tools：** Bash, Read, Grep, Glob, Write, Agent, WebSearch, AskUserQuestion
> **来源：** `cso/SKILL.md`

---

## 一、为什么这个 Skill 存在

**问题：** AI 代码审查工具通常只检查应用层漏洞（SQL 注入、XSS），但现实中大多数安全事件发生在基础设施层——泄露的密钥、未固定的 CI/CD Action、未签名的 Webhook。

**传统方案：** 聘请安全顾问做季度审计，或用 SAST 工具扫描代码。问题是：SAST 工具产生大量误报，安全顾问费用高且频率低。

**gstack 的方案：** 一个 15 阶段的安全审计 Skill，从基础设施开始（secrets 考古、供应链、CI/CD 管道），然后才进入应用代码。每个发现都由独立子 Agent 验证——消除锚定偏差。v2 相比 v1 的关键改进：先检测技术栈再扫描，用 Grep 工具代替 bash grep。

## 三、关键机制

### 3.1 零噪音误报过滤

17 条硬排除规则 + 9 条来自 Anthropic 安全审查方法论的先例：
- DOS 不是发现
- 测试文件不是攻击面
- React 默认 XSS 安全
- 置信度 < 8/10 的发现不进入报告（daily 模式）

### 3.2 独立验证

每个候选发现由一个**只看到发现和误报规则**的全新子 Agent 验证——不受初始扫描的锚定偏差影响。验证失败的发现静默丢弃。

### 3.3 变体分析

当一个漏洞被确认后，自动搜索整个代码库寻找**相同模式**的其他实例。

### 3.4 趋势追踪

发现被指纹化并跨审计运行追踪。可以看到：什么是新的、什么已修复、什么被忽略。

## 四、三种运行模式

| 模式 | 置信门控 | 用途 |
|------|---------|------|
| `--daily` | 8/10 | 零噪音日常扫描，只报告高置信度发现 |
| `--comprehensive` | 2/10 | 月度深度扫描，挖出所有值得调查的 |
| `--diff` | 8/10 | 作用域限于当前分支变更，适合 PR 前安全检查 |

## 六、Prompt Engineering 可迁移模式

### 模式 1：基础设施优先
先检查最常被忽视但最危险的层面（密钥泄露、CI/CD），再检查应用层。

### 模式 2：独立验证消除偏差
用隔离的子 Agent 验证发现，防止"自己验证自己"的确认偏差。

### 模式 3：置信度门控
不同场景使用不同的报告阈值——日常需要零噪音，深度审计需要低阈值。

### 模式 4：变体搜索
找到一个漏洞后，搜索整个代码库的相同模式——一个 bug 通常不是孤例。
