# L6：元哲学层 — 五个设计哲学 + 跨领域迁移框架

> 最抽象的层级：从 gstack 提取的设计哲学，可以应用到任何 AI Agent 系统。

---

## 1. 五大设计哲学

```
┌─────────────────────────────────────────────────────────────────┐
│                                                                  │
│               gstack 的五大设计哲学                               │
│                                                                  │
│  ┌───────────────────────────────────────────────────────────┐  │
│  │  φ1: 姿态 > 内容 （Posture over Content）                 │  │
│  │                                                           │  │
│  │  不要告诉 AI "检查 SQL 注入"                               │  │
│  │  要告诉 AI "你是一个偏执的安全审计员，你相信任何输入都是攻击" │  │
│  │  → AI 自己知道检查什么，缺的是"从什么角度看"                │  │
│  │                                                           │  │
│  │  原理：LLM 的训练数据中有安全知识，但需要正确的认知姿态     │  │
│  │        来激活这些知识。姿态是知识的索引键。                  │  │
│  └───────────────────────────────────────────────────────────┘  │
│                                                                  │
│  ┌───────────────────────────────────────────────────────────┐  │
│  │  φ2: 过程 > 产出 （Process over Output）                   │  │
│  │                                                           │  │
│  │  价值不在最终报告——价值在强制走完每一步。                    │  │
│  │  因为 AI 的危险不是"给出错误答案"                           │  │
│  │  而是"沉默地跳过了它不确定的部分"。                         │  │
│  │                                                           │  │
│  │  原理：检查清单的价值 = 防止沉默遗漏。                      │  │
│  │        即使每一项都标记 N/A，强制检查的行为本身就是保障。    │  │
│  └───────────────────────────────────────────────────────────┘  │
│                                                                  │
│  ┌───────────────────────────────────────────────────────────┐  │
│  │  φ3: Boil the Lake — AI 让完整性几乎免费                    │  │
│  │                                                           │  │
│  │  人工审查 80 项设计清单要 4 小时 → 只检查"重要的" → 遗漏    │  │
│  │  AI 审查 80 项设计清单要 10 分钟 → 全部检查 → 不遗漏       │  │
│  │                                                           │  │
│  │  原理：当完整性的边际成本趋近于零时，永远选择完整方案。      │  │
│  │        "我没时间做完"不再是有效的借口。                      │  │
│  └───────────────────────────────────────────────────────────┘  │
│                                                                  │
│  ┌───────────────────────────────────────────────────────────┐  │
│  │  φ4: 约束 > 自由 — 限制 AI 比放开 AI 更有效                │  │
│  │                                                           │  │
│  │  /qa-only 不给 Edit 工具 → 物理上不能改代码 → 纯报告       │  │
│  │  "不要读源码" 作为自然语言规则 → 软约束                     │  │
│  │  两层约束同时存在 → 深度防御                                │  │
│  │                                                           │  │
│  │  原理：AI 的"有帮助"本能会驱使它超出边界。                  │  │
│  │        明确的约束比模糊的自由更可预测。                      │  │
│  └───────────────────────────────────────────────────────────┘  │
│                                                                  │
│  ┌───────────────────────────────────────────────────────────┐  │
│  │  φ5: 锚定 > 叙事 — 没有数据的评价是噪音                    │  │
│  │                                                           │  │
│  │  "做得很好" → 噪音                                         │  │
│  │  "47 个 commit，测试比例 38%，最大交付是 cookie 导入" → 信号│  │
│  │                                                           │  │
│  │  原理：AI 特别擅长生成听起来合理的空洞叙事。                │  │
│  │        强制数据锚定是对抗 AI slop 的最有效机制。             │  │
│  └───────────────────────────────────────────────────────────┘  │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘
```

## 2. 哲学的因果关系

```
φ1 姿态 > 内容
    │
    ├──► φ2 过程 > 产出     姿态决定视角，过程确保视角被完整应用
    │        │
    │        └──► φ3 Boil the Lake   有了过程就要做完，AI 让做完变便宜
    │
    └──► φ4 约束 > 自由     姿态本身就是一种约束（限定视角）
             │
             └──► φ5 锚定 > 叙事    约束的一种：强制叙事锚定在数据上

因果链：
  姿态（选择视角）
    → 过程（强制走完）
      → 完整性（AI 让完整变便宜）
    → 约束（限制行为边界）
      → 锚定（限制叙事边界）
```

### 4.2 迁移到新领域的五步协议

```
Step 1: 确定你的"OODA 循环"
  问：在你的领域，观察→定向→决策→行动 分别是什么？
  例（医疗）：问诊→诊断→治疗方案→执行治疗
  例（投资）：研究→估值→决策→交易执行

Step 2: 为每个阶段选择姿态（φ1）
  问：这个阶段需要什么视角？谁的判断框架最适合？
  例（医疗诊断）：House MD 式鉴别诊断 vs 贝叶斯概率更新
  例（投资估值）：Graham 价值投资 vs Thiel 垄断思维

Step 3: 为每个阶段设计检查清单（φ2 + φ3）
  问：这个阶段的"沉默遗漏"是什么？什么东西被跳过会是灾难？
  例（医疗）：药物相互作用检查、过敏史确认
  例（投资）：关联方交易、现金流质量检查

Step 4: 设置风险门控（φ4）
  问：什么操作不可逆？什么条件下必须暂停让人类决定？
  例（医疗）：高风险手术需要二次意见
  例（投资）：超过仓位限制需要审批

Step 5: 设计反馈循环
  问：怎么从每次运行中学习？需要持久化什么数据？
  例（医疗）：治疗结果追踪 → 影响下次诊断偏好
  例（投资）：交易复盘 → 影响下次估值模型参数
```

## 5. 60 秒摘要

**gstack 的本质是五个设计哲学（姿态>内容、过程>产出、完整性免费、约束>自由、数据>叙事）通过六个可组合模式（姿态、清单、循环、门控、锚定、持久化）在三层反馈循环（分钟/小时/周）中运转。** 理解这句话就理解了整个系统。迁移到新领域时，先确定你的 OODA 循环，再为每个阶段选姿态、设清单、加门控、接循环——你就有了自己的 gstack。
