# L1：单 Skill 解剖层 — 通用骨架图

> 每个 Skill 模板都遵循同一个骨架结构。理解这个骨架 = 能读懂任何 Skill。

---

## 3. 骨架的四个变体

虽然骨架相同，但步骤序列区有四种不同的"执行拓扑"：

```
变体 A：线性序列（Linear）
━━━━━━━━━━━━━━━━━━━━━━
Step 1 → Step 2 → Step 3 → Step 4 → 输出
代表：/ship, /document-release, /setup-browser-cookies

变体 B：分支序列（Branching）
━━━━━━━━━━━━━━━━━━━━━━━━
Step 0: 选择姿态/模式
  ├── 姿态 A → Step 1a → Step 2a → ...
  ├── 姿态 B → Step 1b → Step 2b → ...
  └── 姿态 C → Step 1c → Step 2c → ...
代表：/plan-ceo-review（4 种姿态）, /qa（3 层严重度）

变体 C：循环序列（Looping）
━━━━━━━━━━━━━━━━━━━━━━━
Step 1 → Step 2 → Step 3 ──┐
                   ↑         │
                   └── 如果未通过 ──┘
                   │
                   ▼ 如果通过
              Step 4 → 输出
代表：/qa（test→fix→retest）, /design-review（audit→fix→re-audit）

变体 D：双 Pass 序列（Multi-Pass）
━━━━━━━━━━━━━━━━━━━━━━━━━━
Pass 1（严格）: 全部发现 → 分类
  │
  ▼
Pass 2（宽松）: 全部发现 → 分类
  │
  ▼
合并 → 排序 → 处理
代表：/review（CRITICAL + INFORMATIONAL）
```

## 4. 迁移清单：构建新 Skill 时的检查项

```
□ 元数据区
  □ 名称和一句话描述
  □ allowed-tools 列表（最小权限原则）
  □ 模型选择（sonnet 够用不要用 opus）

□ 角色定义区
  □ 具体角色名称（不要"一个工程师"，要"Staff 级别的后端工程师"）
  □ 核心公理（这个角色最坚信什么？）
  □ 优化目标（这个角色最在意什么单一变量？）
  □ 认知模式表（可选，但对 plan 类 Skill 极有价值）

□ 步骤序列区
  □ Step 0 预飞行检查
  □ 选择执行拓扑：线性/分支/循环/多Pass
  □ 每步标记输入和输出
  □ 高风险操作插入 AskUserQuestion 门控
  □ 最后一步输出摘要

□ 规则与约束区
  □ 至少一条"永远不要"规则
  □ 至少一条输出格式规则
  □ 错误恢复指令（"如果 X 失败，则做 Y"）
```
